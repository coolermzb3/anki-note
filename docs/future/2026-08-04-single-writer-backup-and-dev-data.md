# 单写入者备份与开发数据隔离

状态：未来重构方向，首次记录于 2026-08-04。当前实现仍以 [清唱工作区](../vocal-pitch-workspace.md#保存与备份) 和现有备份代码为准；本文不代表已经排期。

## 决策摘要

把目录备份从“两个可独立前进的副本之间自动同步”收缩为两项单向能力：

1. 当前浏览器把完整事实单向增量镜像到一个可写目录；目录不参与版本竞争。
2. 用户明确确认后，从一个只读来源完整重置当前浏览器；浏览器原数据直接丢弃，不合并。

正式部署和本地开发分别拥有自己的可写目录。dev/preview 可以记住正式备份目录作为只读重置来源，但 dev/preview 的任何自动写入路径都不能接触它。

```text
deploy 浏览器 ──单向增量写入──> 正式备份目录

正式备份目录 ──显式完整重置──> dev/preview 浏览器
dev/preview 浏览器 ──单向增量写入──> 开发备份目录
```

禁止 dev/preview 自动写回正式目录，也不提供把开发数据自动提升为正式数据的能力。

## 为什么这样简化

当前复杂度主要来自浏览器和目录都可能在上次共同版本后独立变化。系统因此必须保存共同基线、区分单边与双边变化、传播删除、阻止旧快照回退，并在学习域和清唱素材域分别解决冲突。

单写入者模型预先指定权威源：

- 执行备份时，浏览器是权威源，目录只是派生镜像；
- 执行重置时，用户选定的目录是本次权威源，浏览器内容可丢弃。

目标看起来“更新”时也不会获得参与合并的资格。外部修改只表示目录损坏、被误用或需要显式恢复，不再触发自动三方合并。

仍需保留摘要校验、增量文件复用、删除传播、清单最后提交、格式迁移和中断恢复。这些属于可靠备份，不属于多副本合并。

## 数据流与不变量

| 流程 | 读取 | 写入 | 用途 |
| --- | --- | --- | --- |
| 正式备份 | 正式浏览器 | 正式目录 | 普通用户日常备份与灾难恢复 |
| 开发备份 | dev/preview 浏览器 | 开发目录 | 独立积累和备份开发数据 |
| 用正式数据重置开发环境 | 正式目录 | dev/preview 浏览器；成功后写开发目录 | 把正式数据复制到开发环境 |

“正式只读来源”描述的是正式目录在 dev/preview 重置流程中的权限，不是整个流程没有写入。重置会改写开发浏览器，成功后再通过通用单向写入能力更新开发目录；正式目录在开发环境中始终只读，只有正式部署可以把日常备份写入其中。

实现必须维持以下不变量：

1. 一个活动备份目录只有一个写入者配置；普通备份永远不会从目录自动导入。
2. dev 的正式只读来源只能进入读取和重置流程，不能传给任何备份写入函数。
3. dev 的可写目录必须与正式只读来源不是同一个目录。
4. 重置覆盖学习域和清唱素材域，包括应用设置、练习、默写、录音、上传文件和分析缓存。
5. 环境级备份状态和 dev 专属配置不属于应用数据：重置时保留当前开发写入目录句柄、正式只读来源和本地模式，也不会把它们传播到正式浏览器。
6. 练习、录音或其他持久化活动进行中不能重置数据库。
7. 导入失败时保持原浏览器数据；导入成功后即使开发目录写入失败，也保留已经完成的浏览器重置并明确提示未备份。
8. 活动开发目录只镜像当前开发浏览器，不承担版本历史；重置后的镜像会覆盖其中的旧开发数据。

## 普通备份与恢复

设置页现有“选择目录”始终选择当前浏览器的可写备份目录：

- 普通用户选择正式目录；
- dev/preview 选择独立的开发目录，并显示不得选择正式目录的警告；
- 两种环境调用完全相同的单向写入能力，备份核心不判断 dev 或 deploy。

第一次选择可写目录时，可以接受空目录或已经属于当前角色的备份目录。写入器以浏览器当前状态为准：复用未变化的日文件和音频文件，写入变化内容，删除目标中已经不属于当前数据集的文件，并最后提交清单。

如果可写目录的内容被其他写入者改变，不能自动导入或合并。界面只提供以下恢复路径：

- 改选目录；
- 明确确认后，用当前浏览器重新建立目录镜像；
- 明确执行“从备份恢复”，用目录完整重置浏览器。

恢复始终是显式破坏性操作，必须先验证完整清单和文件摘要，再开始替换 IndexedDB。它不能与普通页面进入检查绑定。

## dev/preview 专属工具

### 本地模式入口

当前主机是 `localhost`、`127.0.0.1` 或其他明确允许的回环地址时，设置页默认显示一个“正式预览 / 开发模式”切换按钮，不依赖 URL 参数：

- 首次打开默认为“开发模式”，显示开发数据折叠区；
- “正式预览”隐藏开发工具，使页面接近正式部署界面；
- 切换按钮在两种模式下都保留，避免进入正式预览后无法切回；
- 非回环地址不显示切换按钮和开发数据区。

“正式预览”只是本地界面模式，不会把当前 origin 变成正式数据环境，也不会切换到正式备份目录。两种模式继续使用同一份本地浏览器数据和开发写入目录；正式目录在两种模式下都只能由显式重置流程读取。

不要只使用 `import.meta.env.DEV` 判断入口，因为 `pnpm preview` 是生产构建。主机限制负责阻止正式部署显示入口，持久化模式只负责本地界面切换。

当前 `dev` 和 `preview` 脚本都使用 `http://127.0.0.1:6136`，因此它们共享 IndexedDB、目录句柄和开发工具设置。以后改变协议、主机或端口时，应把它视为新的独立开发环境。

运行时隐藏已经足够：这些工具只能修改当前 origin 的浏览器数据和用户明确授权的目录，不构成服务端权限边界。除非以后出现真实风险，不为构建时剔除再维护第二套构建流程。

### 独立代码与配置

dev 专属实现集中在独立模块中，例如：

```text
src/debug/DevBackupTools.tsx
src/debug/devBackupProfile.ts
```

正式组件只保留一次条件渲染。普通备份读写、清唱保存和练习流程中不得散布 dev 分支。

目录句柄不能靠普通 JSON 中的路径恢复访问权限，因此运行时选择不能只写入一个文本配置文件。推荐建立独立的 `anki-note-dev-tools` IndexedDB，只保存 dev 专属信息：

```ts
interface DevBackupProfile {
  id: "default";
  uiMode: "formal-preview" | "development";
  developmentWriterId: string;
  formalSourceDirectoryHandle?: FileSystemDirectoryHandle;
  formalSourceDirectoryName?: string;
  lastResetAt?: string;
}
```

开发可写目录仍使用通用备份状态，因为“当前浏览器向哪个目录写入”不是 dev 特有概念。开发写入者 ID、正式只读来源、本地模式和最近重置时间放在独立数据库中，不受应用数据完整重置影响，也不进入备份。

每个开发可写目录必须包含一个很小的角色标记文件。它负责标识目录用途和当前写入者，不负责保存浏览器权限句柄。例如：

```json
{
  "schemaVersion": 1,
  "role": "development",
  "writerId": "..."
}
```

选择开发可写目录时按以下规则处理：

- 空目录：先写入开发标记，再登记为活动目录；
- 标记中的 `writerId` 与当前 `developmentWriterId` 相同：作为当前环境已有目录重新连接；
- 标记是 `development`、但 `writerId` 不同：默认拒绝；用户确认原写入者已经停用后，可以执行“重新采用开发目录”，以当前 ID 改写标记；
- 非空且没有开发标记：直接拒绝，不从备份清单猜测它是旧开发目录还是正式目录。迁移时选择新的空目录，由当前浏览器重新建立开发镜像。

每次写入前都必须重新读取标记并核对 `writerId`。目录被另一个环境重新采用后，旧环境即使仍持有写权限也会因 ID 不匹配而停止写入。这不能阻止绕过应用直接修改文件，但能维持应用内部的单活动写入者约束。

### 开发数据区操作

开发数据区至少提供：

- 选择或更换正式只读来源；
- 从已记住的正式来源重置当前开发数据；
- 忘记正式只读来源；
- 查看当前开发可写目录，并跳转到普通备份设置进行更换；
- 清空当前开发数据。

正式来源目录句柄应被记住，不要求每次重选。点击重置时先用该句柄查询读取权限；权限过期时在这次用户手势内请求恢复。只有句柄失效、目录移动或用户拒绝权限时，才要求重新选择目录。

选择正式来源时只请求读取权限，不创建角色标记，不修改清单，也不把它登记为活动备份目录。若浏览器支持目录身份比较，应同时拒绝把同一目录设为开发写入目标和正式读取来源；角色标记作为持久的第二层保护。

## 开发数据重置流程

“从正式备份重置开发数据”执行以下固定流程：

1. 确认没有活动练习、录音、分析写入或其他未保存工作。
2. 使用已记住的正式来源句柄申请读取权限。
3. 读取并验证清单、全部学习数据、清唱素材及其内容摘要。
4. 展示来源目录、数据时间、练习/默写数量和清唱素材数量。
5. 明确提示当前开发数据及活动开发目录中的旧镜像将被覆盖，并等待确认。
6. 在同一个 IndexedDB 事务中替换应用设置、练习、默写和清唱素材；事务失败时回滚原数据。
7. 保留独立 dev-tools 配置和当前开发可写目录句柄。
8. 如已配置开发可写目录，立即把重置后的浏览器状态镜像过去；不得访问正式来源的写入接口。
9. 刷新应用状态，并报告浏览器重置和开发备份各自的结果。

活动开发目录不是历史归档。即使它刚完成备份，第 8 步及后续普通备份仍会尝试把它更新为重置后的状态；一次写入失败也不构成保留承诺，因此不能靠“已经备份”保留旧开发数据。

确认重置即明确丢弃旧开发数据，不提供快照、开发记录标记或合并到正式目录等保留路径。这些能力都会重新引入版本、引用和冲突语义，与本次简化目标相反。

## 建议的代码边界

实施时先把当前大文件按稳定职责拆分，而不是按 dev/deploy 复制两套逻辑：

```text
src/data/backup/
├─ capabilities.ts  # 构造不透明的只读来源和已验证可写目标
├─ inspect.ts       # 读取和验证目录，不决定业务动作
├─ read.ts          # 构造完整可恢复数据集
├─ write.ts         # 浏览器到目录的单向增量镜像
├─ restore.ts       # 已验证数据集到浏览器的完整替换
└─ types.ts

src/debug/
├─ DevBackupTools.tsx
└─ devBackupProfile.ts
```

目录选择后先通过工厂转换成两种不透明 capability：

- `BackupReadSource` 只要求读取权限，可用于 `inspect` / `read` / `restore`；
- `BackupWriteTarget` 要求读写权限和合法目录角色；开发目标还必须具有匹配的写入者 ID。它是 `write` 唯一接受的目录参数。

两种 capability 都带有模块私有的 `unique symbol` 品牌，只能由 `capabilities.ts` 中的工厂构造，裸句柄无法通过结构类型伪装。正式只读来源从独立数据库取回裸句柄后，只能由只读工厂构造 `BackupReadSource`；可写工厂不接受正式来源配置。正式设置页和 dev 工具共享底层读取、恢复和写入能力，但类型和工厂边界保证正式来源不能误入写入路径。

## 分阶段迁移

### 阶段一：固定单向基础能力

- 从现有实现中提取目录检查、完整读取、增量写入和完整替换；
- 保持现有清单、日期分片、音频二进制文件和内容摘要兼容；
- 为写入中断、删除传播、损坏文件和大音频复用建立直接测试；
- 暂时不改变现有用户可见同步行为。

### 阶段二：加入开发数据区

- 建立独立 dev-tools 配置库并记住正式只读来源；
- 在设置页加入无需 URL 参数的“正式预览 / 开发模式”切换；
- 加入强制开发目录标记、逐次写入者校验、显式重新采用和同目录拒绝；
- 加入只读来源与已验证可写目标的 capability 边界；
- 实现完整重置以及重置后写入开发目录；
- 在 dev 与 preview 实际验证目录权限恢复和数据隔离；
- dev/preview 的活动开发目录从此只走新单向写入路径；正式部署可以暂时保留旧同步编排。

### 阶段三：把正式备份切换为单写入者语义

- 取消进入练习、清唱和默写前的目录自动导入；
- 普通活动完成后只执行浏览器到目录的增量写入；
- 设置页保留显式完整恢复和重新建立备份；
- 把“数据冲突”改成更准确的目录外部修改或完整性错误提示；
- 为已有目录提供一次明确的采用或重新建立流程，不静默改变权威源。

### 阶段四：删除多主同步兼容层

在新语义经过实际使用并确认不再需要 dev/deploy 自动互相合并后，删除：

- 上次共同摘要和按域三方决策；
- 自动 `use-browser` / `use-backup` 选择；
- 学习域与清唱素材域的冲突选择界面；
- 为双向自动导入保留的时间戳回退分支；
- 页面进入时为自动导入服务的阻塞式预检。

不要在阶段二就删除这些兼容路径；先证明新的开发工作流足够便利，再缩减正式语义。

## 验收条件

实现完成时至少验证：

1. 正式部署不显示本地模式切换和开发数据区，也无法取得已记住的正式只读来源。
2. 回环地址首次打开默认为开发模式，无需 URL 参数即可切换正式预览和开发模式。
3. 正式预览和开发模式共享当前 origin 的浏览器数据与开发写入目录；两者都不会写正式目录。
4. dev 和 preview 在当前相同 origin 下共享已记住的正式来源、本地模式与开发备份设置。
5. 关闭并重开浏览器后，重置通常只需重新授权，不需重新选择目录。
6. 开发写入目录首次必须为空或已有开发标记；非空无标记目录不能采用，正式目录不能被设为开发写入目标。
7. 从正式来源重置会删除仅存在于开发浏览器中的学习记录和清唱素材；成功路径会把活动开发目录更新为相同状态，目录写入失败则明确标记尚未备份并允许重试。
8. 重置后所有普通保存只写开发目录；测试桩证明正式来源收到零次写操作。
9. 开发目录被重新采用后，旧写入者下一次写入会因 `writerId` 不匹配而停止。
10. 类型测试证明正式只读来源不能传给 `write`，运行时测试证明可写工厂拒绝正式来源配置。
11. 普通备份能增量写入新增、修改和删除，并不会因为目录内容看起来更新而自动导入。
12. 完整恢复在校验失败时不修改浏览器数据。
13. 清唱大文件未变化时不会重新复制；删除素材会从可写目录移除对应音频和分析缓存。
14. dev 专属配置不会出现在正式备份清单、学习设置或清唱素材中。

## 非目标

本方向不提供：

- 多设备同时离线修改后的自动合并；
- dev 数据自动回流或提升到正式数据；
- 同一个目录的多个活动写入者；
- 云数据库、账户系统或后台网络同步；
- 对任意外部手工修改备份文件的语义合并。

如果未来重新要求真正的多设备双向同步，应单独采用服务器权威源或成熟复制协议，而不是再次扩展这个目录备份格式。

## 保留的现有约束

- IndexedDB 继续作为运行时工作数据库，目录用于可恢复备份，参见 [ADR 0004](../adr/0004-indexeddb-with-file-backups.md)。
- 清唱素材在浏览器保存工作副本，在目录保存独立二进制文件，不写成 Base64 JSON，参见 [ADR 0008](../adr/0008-browser-working-copy-with-file-backed-saved-audio.md)。
- 已保存音频继续使用稳定素材 ID 和内容摘要；单向重构不能退化为每次重新扫描或复制所有大型音频。
